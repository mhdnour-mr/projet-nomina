# نموذج الموقع الإلكتروني — توظيف (Ministry of Defense recruitment forms)

تطبيق Flask بسيط (يدعم SQLite) يُدار ثلاث استمارات:

| من يملأ؟ | الاستمارة | المسار | ملاحظة |
|---|---|---|---|
| **المتقدّف** (بدون تسجيل، الواجهة العامة) | الاستمارة 1 — البيانات الشخصية | `/form1` | يملأها المتقدّف فقط، ثم يصل إلى صفحة "تم الاستلام" |
| **اللجنة التخصصية** (`login` مطلوب) | الاستمارة 2 — التقييم التقني | `/form2/<id>` | تُملأ بعد استكمال الاستمارة 1 |
| **اللجنة الإدارية** (`login` مطلوب) | الاستمارة 3 — المراجعة الإدارية | `/form3/<id>` | تُملأ بعد الاستمارة 2 |

بيانات الدخول للجان: `admin` / `admin123`.

## هيكل قاعدة البيانات (SQLite — `nomina.db`)
أربع جداول مترابطة بـ `applicant_id`:
- **users** — حسابات تسجيل الدخول (كلمة مرور مُشفّرة SHA-256).
- **form1_applicant** — البيانات الخاصة بالمتقدّف (الملأه المتقدّف).
- **form2_technical** — التقييم التقني (الملأها اللجنة التخصصية).
- **form3_administrative** — المراجعة الإدارية (الملأها اللجنة الإدارية).

علاقة الربط: `form2.applicant_id` و `form3.applicant_id` → `form1_applicant.id`.
عند حذف متقدّف، تُحذف استماراته الثلاث معه (cascade).

## تشغيل محلي
```bash
python app.py        # يفتح على http://localhost:5000
```

## النشر على Render (رابط دائم)
- الـ repo مرئي على GitHub: https://github.com/mhdnour-mr/projet-nomina
- `render.yaml` موجود — ينشئ خدمة ويب + قرص دائم (`DATA_DIR=/data`) لتخزين `nomina.db`
  بحيث لا تتوقّف البيانات عند إعادة النشر.
- صفحة الضبط: **⚙️ إعدادات** (تغيير كلمة مرور)، و**✏️ تعديل** على صفحة كل متقدّف،
  و**بحث** + **حذف شامل** + **تصدير Excel** في الداشبورد.

## الخصوصية
- الاستمارة العامة (Form 1): مفتوحة للجميع.
- الداشبورد/التصدير/التعديل/الإعدادات: محميّة بتسجيل دخول اللجنة.
